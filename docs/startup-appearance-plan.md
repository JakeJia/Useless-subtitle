## 1. 目标与当前情况

本轮需求来自 Windows 试用，统一适用于支持的平台：启动时有效遮罩集合为空则补建一个默认遮罩；默认不透明度改为 100%；移除可见遮罩边框及边缘阴影。Windows 是主要交互验收平台，macOS 和 Linux 尚未测试。

| 项目 | 开发前实现 | 本次实现目标 | SRS 条款 |
|---|---|---|---|
| 空集合启动 | 仅在 `initialized == false` 且集合为空时创建默认遮罩；已初始化空集合只启动托盘。 | 每次启动在配置读取、恢复和校验后检查集合；为空则补建并保存恰好一个默认遮罩。 | FR-MASK-001、FR-MASK-006、FR-PERSIST-005 |
| 默认不透明度 | Rust 默认、前端初始值、无状态时背景及旧配置缺省值均使用 90%。 | 普通新建及启动补建使用黑色、100%；相关默认值统一。已有有效值和复制继承规则保留。 | FR-APP-002、FR-APP-006、FR-MASK-004 |
| 遮罩边框 | 编辑状态有 1px 白色虚线和内阴影；锁定后移除。 | 两种状态均无可见边框、轮廓线及边缘阴影；保留圆角、编辑工具栏和透明缩放命中区。 | FR-APP-005、FR-INPUT-002、FR-INPUT-006、FR-INPUT-007 |

当前启动读取应用数据目录中的 `mask-state.json`，存在损坏时尝试备份恢复，并支持迁移旧 `store.json`。保存的是遮罩标识、名称、外观和几何信息；锁定、隐藏仅属于运行状态，重启后均恢复为可见、可编辑。普通托盘退出前会刷新待保存数据。

系统托盘指 Windows 任务栏右侧通知区域、Linux 通知区域或 macOS 菜单栏状态项。遮罩窗口目前隐藏任务栏按钮，本轮通过启动时显示遮罩提供反馈。

## 2. 确定的行为

### 2.1 启动与零遮罩

先完成配置读取、备份恢复或旧配置迁移以及数据校验，再决定是否创建默认遮罩：

| 得到的有效集合 | 启动行为 |
|---|---|
| 非空 | 恢复已有遮罩，不额外创建默认遮罩；保留有效保存值，按既有规则恢复到安全可编辑状态及可恢复位置。 |
| 空，包括首次启动和 `initialized == true` 的空配置 | 创建并保存一个默认遮罩：新稳定标识、主屏居中、600 × 120 逻辑像素、黑色、100% 不透明、可见、可编辑，并按显示器范围限制几何信息。 |

运行期间删除最后一个遮罩仍保存空集合，托盘保持可用，当前会话不自动补建。下次启动补建一次；以后启动恢复该记录，避免不断增加遮罩。

空集合判断针对配置读取与校验后的集合。非空配置中窗口创建失败继续遵循 FR-MASK-007 的隔离和错误报告要求，不把所有窗口创建失败视为本轮新增的空配置条件。

### 2.2 默认外观与已有数据

首次启动、空集合启动补建、普通“新建遮罩”统一采用 `#000000`、100% 不透明度。设置范围仍为 10%—100%，步进仍为 10%。

恢复已有遮罩时保留其有效保存值，例如 90% 或 40%；复制遮罩继承源颜色及不透明度。前端初始值和旧配置缺少不透明度时的回退值使用 100%，已有合法字段不被新默认覆盖。维持现有配置结构，本轮无需仅因默认值变化而提升配置 schema 版本或批量迁移数据。

### 2.3 无可见边框

采用无可见边框方案，同时去除遮罩表面的内阴影或其他形成描边的样式。保留现有圆角。黑色、白色或其他颜色遮罩均不得出现白色虚线或额外异色描边。

八方向缩放区域继续透明接收鼠标事件，保持原有命中尺寸和方向光标。工具栏、按钮及设置控件自身的边框可以保留。锁定时仍隐藏编辑控件并启用鼠标穿透。

## 8. Windows 原生阴影补充修复

v0.1.6 发布后，用户仍观察到灰色细边。复查确认上一轮只移除了 CSS 边框与内阴影，未关闭原生窗口阴影。Tauri 的 Windows 无装饰窗口默认阴影会引入额外框线，因此上一轮 Linux 检查不能证明 Windows 已满足 FR-APP-005。

补充修复仅在遮罩窗口创建时设置 `shadow(false)`。依赖路径 review、回归结果、Windows 几何及交互待验项目见[原生阴影修复 review](./native-shadow-review.md)。本节修正实现状态，不改变三项需求或配置格式。
