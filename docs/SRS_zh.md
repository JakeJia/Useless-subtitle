# 软件需求规格说明书

> **产品名称：** Useless Subtitle
>
> **文档版本：** v0.4
>
> **状态：** v0.1.6 已发布；原生阴影补充修复纳入 0.1.7 未发布测试构建，Windows/macOS 交互待验证
>
> **实现基线：** v0.1.6，前一版本为 v0.1.5
>
> **最后更新：** 2026-10-15
>
> **事实来源：** 本文档与英文版本定义相同需求。只有两份文档与实现保持一致时，对应功能才具备发布条件。

## 1. 目的与范围

Useless Subtitle 是一款轻量桌面工具，可在视频播放器或浏览器内容上方放置一个或多个可配置遮罩窗口。主要用途是遮挡不需要的硬字幕，同时保留下层应用控件的操作能力。

本次范围沿用 v0.1.5 基线：遮罩生命周期管理、外观控制、原生移动和缩放、安全鼠标穿透、系统托盘恢复、多遮罩持久化以及显示器/DPI 感知恢复。

v0.4 新增三项要求：启动时经校验的遮罩集合为空则创建一个默认遮罩；新建默认遮罩使用 100% 不透明度；移除遮罩可见边框及边缘阴影。v0.1.6 已实现启动及默认不透明度调整，并移除 CSS 边框和内阴影；后续 Windows 反馈暴露出原生窗口阴影仍被开启，[原生阴影修复 review](./native-shadow-review.md)记录补充修复及回归检查。[启动与外观开发计划](./startup-appearance-plan.md)保留原实施和发布记录。

三项要求统一适用于支持的平台。现有试用反馈来自 Windows；有限的 Linux X11 交互检查已通过，Windows/macOS 交互仍待验证。共享代码和打包成功不代表这些平台已通过交互验证。

### 1.1 支持平台

- **一级支持：** Windows 10/11 x64。
- **一级支持：** macOS 11 及以上，Intel 与 Apple Silicon。
- **二级/实验性支持：** Linux x64。托盘、透明、鼠标穿透和置顶行为可能因桌面环境及显示服务器而异。

### 1.2 术语

| 术语 | 定义 |
|---|---|
| 遮罩 | 一个用于遮挡部分屏幕的无边框置顶窗口。 |
| 编辑模式 | 遮罩接收鼠标输入，并提供移动、缩放、设置、锁定和删除控件。 |
| 锁定模式 | 遮罩忽略鼠标输入，使点击和滚轮事件传递给下层应用。 |
| 隐藏 | 遮罩窗口不可见。可见性与编辑/锁定模式相互独立。 |
| 系统托盘 | Windows/Linux 通知区域或 macOS 菜单栏状态项。 |
| 逻辑像素 | 用于跨显示器保持视觉尺寸的 DPI 无关单位。 |

## 2. 状态模型

每个持久化遮罩都具有稳定标识、名称、外观和几何信息。运行时行为由三个独立维度表示：

- **生命周期：** 存在或删除中。
- **可见性：** 可见或隐藏。
- **交互模式：** 编辑或锁定。

锁定和隐藏属于运行时安全状态，应用重启后不恢复。所有恢复的遮罩均以可见、编辑模式启动。

应用运行期间允许不存在任何遮罩。关闭最后一个遮罩不会退出应用，托盘继续可用，当前会话不自动补建遮罩。每次启动先执行配置读取、恢复和校验：遮罩集合非空时恢复已有遮罩，不额外新建；集合为空时创建并持久化恰好一个默认遮罩，包括已初始化的空配置。

## 3. 功能需求

### 3.1 遮罩创建与生命周期

- **FR-MASK-001：** 每次启动时，配置读取、恢复和校验后的遮罩集合若为空，应创建并持久化恰好一个可见、可编辑的默认遮罩，不受已保存初始化标志的影响。遮罩应在主显示器中央，默认逻辑尺寸为 600 × 120，并遵循显示器范围限制，外观采用 FR-APP-002 的默认值。集合非空时应恢复已有遮罩，不额外新建默认遮罩。
- **FR-MASK-002：** “新建遮罩”应创建具有稳定 UUID 标识的可见、可编辑遮罩，并立即持久化。
- **FR-MASK-003：** 新遮罩应在当前或主显示器上采用错位排列，并限制在其工作区内。
- **FR-MASK-004：** 遮罩可以复制其外观和尺寸，但副本必须取得新标识以及不重叠的错位位置。
- **FR-MASK-005：** 关闭遮罩应移除其持久化记录并关闭窗口。持久化失败不得造成关闭控件失去响应；应用状态服务应报告错误并重试。
- **FR-MASK-006：** 删除最后一个遮罩后应持久化空集合，并在当前会话内保持仅托盘运行。下次启动应按 FR-MASK-001 创建一个默认遮罩。
- **FR-MASK-007：** 窗口创建失败不得终止进程。无效条目应被跳过并报告，其他有效遮罩继续加载。

### 3.2 外观

- **FR-APP-001：** 每个遮罩应独立保存六位 `#RRGGBB` 颜色以及 10 至 100 的整数不透明度。
- **FR-APP-002：** 默认外观应为 `#000000`、100% 不透明度，适用于首次启动、空集合启动补建以及普通“新建遮罩”。前端初始值，以及旧配置缺少已保存外观值时使用的默认值，应与此一致。
- **FR-APP-003：** 不透明度控件应使用 10% 步进。文档统一使用“不透明度”；100% 表示完全不透明。
- **FR-APP-004：** 外观修改应立即预览，并通过集中状态服务持久化。
- **FR-APP-005：** 遮罩颜色区域在编辑和锁定模式下均不得显示可见边框、轮廓线或边缘阴影，包括原生窗口阴影或框线；可以保留圆角。编辑模式应保留可见工具栏，锁定模式应隐藏编辑控件。本条约束遮罩表面，不限制工具栏和设置控件自身的边框。
- **FR-APP-006：** 恢复已有遮罩时应保留其有效的已保存颜色及不透明度，包括低于 100% 的值。复制遮罩应按 FR-MASK-004 继承源遮罩外观。修改默认值不得覆盖已保存的外观值。

### 3.3 鼠标与点击行为

- **FR-INPUT-001：** 编辑模式下，在遮罩空白区域按住鼠标主键应移动窗口。
- **FR-INPUT-002：** 八个透明缩放命中区应调用对应原生方向：North、South、East、West、NorthEast、NorthWest、SouthEast 和 SouthWest。移除可见边框不得移除或缩小这些命中区，也不得移除对应方向的鼠标光标反馈。
- **FR-INPUT-003：** 缩放区和工具栏区域不得触发窗口移动。
- **FR-INPUT-004：** 未产生移动的空白区域点击只能激活遮罩；双击不得最大化或锁定遮罩。
- **FR-INPUT-005：** 右键和本地设置按钮应打开相同的遮罩菜单。
- **FR-INPUT-006：** 编辑模式下应显示包含设置、锁定和删除的紧凑工具栏。控件必须使用具备无障碍属性的真实按钮，并在编辑时保持可见。
- **FR-INPUT-007：** 遮罩最小逻辑尺寸应为 96 × 32，确保所有编辑控件均可操作。
- **FR-INPUT-008：** 菜单和外观控件不得受遮罩 WebView 边界限制；应使用原生菜单或独立设置窗口。

### 3.4 锁定与鼠标穿透

- **FR-LOCK-001：** 锁定应隐藏编辑界面并启用整个窗口的鼠标事件穿透，包括点击和滚轮。
- **FR-LOCK-002：** 完全锁定的遮罩不得提供窗口内解锁控件，因为窗口无法接收鼠标输入。
- **FR-LOCK-003：** 只有系统托盘可用后才能启用锁定。如果平台无法提供恢复入口，锁定必须保持禁用。
- **FR-LOCK-004：** 原生穿透切换失败时，遮罩必须保持或返回编辑模式，并显示可恢复错误。
- **FR-LOCK-005：** 解锁时必须先关闭鼠标穿透，再显示编辑控件。
- **FR-LOCK-006：** 托盘必须提供“全部解锁”和针对单个遮罩的“显示并编辑”。
- **FR-LOCK-007：** 本次范围不要求全局键盘快捷键。
- **FR-LOCK-008：** 锁定状态不得持久化；每次启动都必须处于安全可编辑状态。

### 3.5 系统托盘

- **FR-TRAY-001：** 进程运行期间托盘必须始终可用，包括不存在遮罩时。
- **FR-TRAY-002：** 平台允许时，托盘主键和副键操作都应显示菜单，避免仅能通过隐藏点击行为执行命令。
- **FR-TRAY-003：** 顶层菜单应提供新建遮罩、显示全部或隐藏全部、全部解锁、逐个遮罩控制、找回屏幕外遮罩、已实现时的偏好设置，以及退出。
- **FR-TRAY-004：** 显示全部和隐藏全部应为所有遮罩设置一个明确状态，不得逐个反转当前状态。
- **FR-TRAY-005：** 显示全部应保留锁定模式；全部解锁应保留可见性。
- **FR-TRAY-006：** 单个遮罩的“显示并编辑”应显示、解锁并聚焦所选遮罩。
- **FR-TRAY-007：** 托盘操作只能作用于已注册遮罩，不得影响设置或其他工具窗口。
- **FR-TRAY-008：** 退出前必须刷新待写入配置。

### 3.6 设置界面

- **FR-SET-001：** 右键或设置按钮应提供外观设置、锁定、重置几何信息、复制和删除操作。
- **FR-SET-002：** 自定义颜色和不透明度应使用一个可复用、不会鼠标穿透的独立设置窗口，并关联当前选中遮罩。
- **FR-SET-003：** 关闭设置窗口不得关闭或删除其遮罩。
- **FR-SET-004：** 平台支持时，Escape 应关闭临时菜单或设置界面。

### 3.7 持久化与恢复

- **FR-PERSIST-001：** Rust 必须成为完整遮罩集合的唯一状态所有者。前端窗口不得对共享数组执行读改写操作。
- **FR-PERSIST-002：** 配置必须包含模式版本和稳定遮罩标识。
- **FR-PERSIST-003：** 状态写入必须串行化。几何事件应防抖，应用退出时应刷新待处理修改。
- **FR-PERSIST-004：** 配置写入应采用原子写入或具备等效崩溃安全性的方案，并保留可恢复的最近有效副本。
- **FR-PERSIST-005：** 配置缺失时应按现有旧配置迁移规则处理，否则生成首次启动默认值。配置损坏时应保留原文件供诊断，并替换为安全有效配置；存在有效备份时应恢复备份。读取、恢复、适用时的旧配置迁移和校验后的集合应遵循 FR-MASK-001：非空则恢复已有遮罩，空集合则创建并持久化一个默认遮罩。已有有效外观值应按 FR-APP-006 保留。
- **FR-PERSIST-006：** 使用前必须校验颜色、不透明度、尺寸、标识以及配置版本。
- **FR-PERSIST-007：** 单个遮罩记录失败不得阻止其他有效遮罩或托盘启动。

### 3.8 多显示器与 DPI

- **FR-DISPLAY-001：** 保存的几何信息应使用逻辑尺寸和显示器相对逻辑偏移，并包含足够的显示器信息用于选择恢复目标。
- **FR-DISPLAY-002：** 原生窗口 API 返回的物理值必须使用对应显示器缩放比例转换后再持久化或恢复。
- **FR-DISPLAY-003：** 恢复时应优先使用原显示器；原显示器未连接时回退到主显示器。
- **FR-DISPLAY-004：** 恢复的几何信息必须被限制，使至少 48 × 24 逻辑像素的可恢复区域位于已连接显示器工作区内。
- **FR-DISPLAY-005：** 显示全部、应用恢复以及找回屏幕外遮罩操作都应重新校验可见窗口几何信息。
- **FR-DISPLAY-006：** 测试必须覆盖负显示器坐标以及 100%、125%、150%、200% 和 Retina 混合缩放。

### 3.9 置顶与平台行为

- **FR-PLATFORM-001：** 遮罩必须无边框、编辑模式下可缩放、颜色区域外透明，并置于普通应用窗口上方。
- **FR-PLATFORM-002：** Windows 构建应使用合适的工具窗口/任务栏隐藏行为以及逐显示器 DPI 感知。
- **FR-PLATFORM-003：** macOS 构建应尽可能使用辅助应用策略以及全屏辅助/Space 行为。
- **FR-PLATFORM-004：** 产品不得声称能够覆盖受保护系统界面、安全提示、独占全屏应用或拒绝置顶提示的环境。
- **FR-PLATFORM-005：** Linux 限制必须在文档中说明，不得描述为一级支持保证。

## 4. 非功能需求

- **NFR-001 可靠性：** 任何用户操作、异常遮罩记录、重复标识、显示器缺失或持久化错误都不得导致应用进程 panic。
- **NFR-002 可恢复性：** 用户应能通过不超过两次菜单选择找回任意锁定或屏幕外遮罩。
- **NFR-003 安全性：** 前端 capability 应限制为遮罩界面必需的具体窗口和命令操作。完成状态重构后不得继续授权前端直接访问 Store。
- **NFR-004 性能：** 几何持久化不得为每个原生移动事件执行一次磁盘写入。空闲 CPU 应在 Release 构建上测量和报告，不使用“接近 0”描述替代数据。
- **NFR-005 资源测量：** 发布验证应记录 1、5、10 个遮罩时的内存占用，使指标符合多 WebView 架构实际情况。
- **NFR-006 无障碍：** 仅图标按钮必须提供无障碍名称和提示。最小遮罩尺寸下鼠标命中区仍必须可操作。
- **NFR-007 本地化：** 英文与中文文档必须保持结构同步。除非一致实现，否则应用界面本地化不属于本次范围。
- **NFR-008 发布安全：** 分支和 PR 工作流可以构建产物，但只有 `v*` tag 可以发布 GitHub Release。
- **NFR-009 分发：** macOS 和 Windows 签名状态必须准确说明。未签名开发产物不得描述为不会出现系统警告的安装包。

## 5. 验收与发布条件

采用 SRS v0.4 的软件版本只有满足以下全部条件才能发布：

1. 前端类型检查和生产构建通过。
2. Rust 格式检查、lint、单元测试以及锁定依赖检查通过。
3. 状态模型、标识、持久化、几何限制和 DPI 转换测试通过。
4. 手工交互检查覆盖移动、所有缩放方向、锁定、鼠标穿透、托盘解锁、删除、零遮罩、多遮罩重启以及屏幕外恢复。
5. GitHub Actions 成功构建 Windows x64、macOS Intel、macOS Apple Silicon 和 Linux x64。
6. Pull Request 已审查并合入 `main`。
7. 同一 `main` 提交通过完整工作流且没有发布 Release。
8. 从已验证的 `main` 提交创建所确定的软件版本 tag（`v<release-version>`）。SRS v0.4 是文档版本，不是软件发布 tag。
9. tag 工作流成功发布预期 Release 产物。

以下验收场景也必须通过。开发计划分别记录已完成的自动检查、Linux 交互检查及待完成的 Windows/macOS 交互验证。

| 编号 | 场景 | 预期结果 |
|---|---|---|
| AC-START-001 | 无配置或已有初始化空集合时启动。 | 出现恰好一个可见、可编辑、黑色、100% 不透明的遮罩，主屏居中，逻辑尺寸 600 × 120 并遵循显示器范围限制；配置中保存其记录。 |
| AC-START-002 | 删除全部遮罩，正常退出后重启；随后再次正常退出并重启。 | 当前零遮罩会话可通过托盘操作；第一次重启补建一个，第二次恢复同一个遮罩，不重复创建。 |
| AC-START-003 | 保存多个具有自定义颜色、不透明度、尺寸和位置的遮罩，包含隐藏或锁定的运行状态，然后重启。 | 标识和数量一致，有效外观与可恢复几何信息正确保留；全部以可见、可编辑状态启动。 |
| AC-START-004 | 主配置损坏但有有效备份，或恢复后得到经校验的空集合。 | 恢复结果非空时不额外新建；为空时创建并保存一个默认遮罩；损坏文件保留供诊断。 |
| AC-APP-001 | 普通新建一个遮罩，并复制一个不透明度为 40% 的已有遮罩。 | 新建遮罩为黑色、100%；副本继承源遮罩颜色及 40% 不透明度。 |
| AC-APP-002 | 恢复已保存的 90% 不透明遮罩，或迁移带有/缺少不透明度值的旧配置。 | 有效保存值不变；旧配置缺少不透明度时默认使用 100%；设置显示值与实际外观一致。 |
| AC-APP-003 | 在编辑和锁定模式下检查不同不透明度的黑色、白色及彩色遮罩；Windows 覆盖 100%、125%、150%、200% 显示缩放及已有遮罩恢复。 | 遮罩直线边缘无可见边框、虚线、轮廓线、原生框线和边缘阴影；可以保留圆角；编辑控件仅在编辑模式显示。 |
| AC-INPUT-001 | 移动无边框遮罩，进行八方向缩放，并在 96 × 32 尺寸操作工具栏。 | 透明命中区和方向光标正常；缩放和工具栏不会触发窗口移动；锁定、鼠标穿透和托盘恢复均正常。 |

Windows 是本次主要手工验证平台。macOS Intel、macOS Apple Silicon 和 Linux 应分别记录实际结果或明确标为待验证，不能把构建成功记为交互测试通过。

## 6. 范围外功能
